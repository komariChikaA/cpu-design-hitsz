1 / 基础问题

流水线是什么？

IF/ID/EX/MEM/WB 分工，不同指令并行占用不同级。提高吞吐，不保证单条延迟。理想 CPI≈1，AXI、load-use、M 扩展使实际更高。

valid / bubble / stall / flush

valid=真实指令；bubble=valid 0；stall=寄存器保持；flush=错误路径 valid 清零。波形先看 valid。

为什么主要是 RAW？

按序发射、执行、提交且单 WB 口，年轻指令不能越过老指令，因此处理后读等待前写的 RAW。

控制冒险

无预测，EX 解析；taken flush IF/ID 和 ID/EX，旧 AXI 取指响应被过滤。

结构冒险

唯一 AXI Master 被取指/数据共享；优先级 data write > data read > instruction read。

VALID/READY

同拍都为 1 才握手。AW/W/B 为写地址/数据/响应，AR/R 为读地址/数据；AW/W 可不同拍。

3 / 五级流水

IF：地址什么时候提出？

// cpu_core.v:43-56, 521-534（搜索 ifetch_addr）
if (ex_bj_f) pc <= ex_bj_target;
else if (ifetch_valid && !stall_if) pc <= pc + 4;
assign ifetch_addr = ex_bj_f ? ex_bj_target : pc;

地址出现不等于取到指令；AR 握手接受地址，R 握手返回数据，ifetch_valid 周期结束时 IF/ID 才锁存。

ID：什么时候译码？

IF/ID 上升沿锁存 id_inst 后，整个周期组合译码、读 RF、扩展立即数；下一上升沿进入 ID/EX。

EX

先选前递操作数，再做 ALU/分支/地址计算；taken 当周期产生 target/flush。

MEM

MREQ 形成地址/WSTRB，MEXT 做 load 子字节扩展，memory_freeze 等 AXI 完成。

WB

wb_valid && wb_rf_we 时写 RF；结果来自 ALU/RAM/PC+4/EXT。

WB_ALU → 算术/AUIPC/M扩展
WB_RAM → load
WB_PC4 → JAL/JALR
WB_EXT → LUI

4 / 冒险处理

普通 RAW

add x3,x1,x2
sub x4,x3,x5

sub 在 EX、add 在 MEM 时 forward=01；生产者在 WB 时 forward=10。MEM 优先。

load-use

lw x2,0(x1)
addi x3,x2,1

stall_if 保持 PC/IF-ID，id_valid_for_ex=0 注入 bubble；数据到 WB 后 forward=10。

store data

rs1 地址和 rs2 写数据分别前递，fwd_store_data 写入 EX/MEM。

控制冒险

EX taken→target+flush；pending address 过滤旧 AXI 返回。

M 长延迟

启动拍即 busy，锁存前递后操作数；完成后进 MEM，bubble 不重启旧 M。

wire load_use_hazard = ex_is_load && ex_rf_we && (ex_rd != 0) &&
 ((id_uses_rs1 && ex_rd == id_rs1) ||
  (id_uses_rs2 && ex_rd == id_rs2));
实板关键 bug：旧逻辑使进入 EX 的 load/M 仍留在 ID，完成后重复执行，UART 状态轮询会把返回值错误前递成地址。最终区分真实依赖、duplicate 和 active freeze，UART/CoreMark 才通过。

7 / AXI 与 MMIO

IDLE
├─ READ  → RADDR --AR--> RDATA --R--> IDLE
└─ WRITE → WSEND --AW和W均完成--> WRESP --B--> IDLE

响应拍防重

Master response 同拍回 IDLE，core 下一沿才撤旧请求；cpu_top 在 response 拍屏蔽请求，AXI Trace 从 41/45 修到 45/45。

过期取指

接受取指时记录 pending word address，返回时仅在它仍等于当前 core 地址时产生 ifetch_valid。

10 / 严格追问

分支罚几拍？
EX 解析后清两个年轻位置；AXI 取指等待还会增加代价，不能说所有情况固定恰好两拍。无预测。
AXI4 还是 AXI4-Lite？
端口保留 AXI4 len/size/burst/last，固定 len=0、单 beat、32 位 INCR，不支持多 outstanding，是单拍 AXI4 子集。
分数为什么不高？
单发射、无 Cache、单事务 AXI、M 多周期；当前先证明持续正确性，后续优化主频、Cache、总线吞吐和乘除法。
WNS 1.702 ns 表示什么？
最差建立时间仍有正余量；TNS=0、0 failing endpoints 表示满足当前时钟约束，改频必须重新实现。
BRAM 为什么 96%？
截图来自带 ILA 构建，ILA 占 BRAM；工程还有 150 KiB 存储。不能当纯 CPU 核心面积。
为什么 Trace/实板两套 ALU？
同一数据通路；Trace 组合 M 匹配参考环境，实板迭代 M 改善时序并用 busy 冻结，不是两套 CPU。
